# Checked ZIP milestone: release and adoption contract

The ordinary ZIP CLI now uses checked synchronous staging for every regular member, including clear Stored files. This is an intentional compatibility restriction: extraction requires ownership-enforced local APFS on macOS, or admitted ext-family/XFS/Btrfs/tmpfs on Linux with the implemented trusted procfs descriptor and ACL facilities. Private-birth, ownership, mode, ACL and identity checks remain enforced. Unlisted destination storage fails closed; there is no fallback to a legacy reader or weaker stage.

Common refused destinations are Linux overlayfs/container root, network mounts, exFAT and macOS HFS+. Users must select supported mounted output and, for encrypted disk snapshots, supported temporary storage (`ZIPFAST_ZIP_TEMP_DIR`). A different temporary directory cannot fix an unsupported output destination. Permission changes do not enable an unlisted filesystem. The full filesystem compatibility goal remains **open** for additional backend support and qualification.

Actual storage qualification covers macOS APFS and Linux ext4, Btrfs and tmpfs. XFS is admitted in code but has not been physically qualified in the retained campaign. Other ext variants are not claimed tested. Carry this exact scope into the release PR, review closure and consumer handoff; do not describe the milestone as universally filesystem-compatible.

The preserved performance evidence belongs to measured Task6/a616 lineage, using rustc1.99.1, matched compiler/lock/profile/features and the recorded binaries. The later review-fix wave has correctness checks, not new performance measurements. Historical near-cap encrypted peak RSS fell from roughly 136–137 MiB to 2.8 MiB, while large AES wall time grew 7–13%, many-small AES 30% and many-small ZipCrypto 333% (roughly 31.6→136.8 ms). These actual-entrypoint costs and measurement limits remain in the [qualification report](validation/encrypted-streaming-2026-11-13.md); they do not support a general speedup or process-wide memory-cap claim.

Generic non-ZIP adoption must separate the original mixed `LegacyDiagnostic` channel from ordered borrowed `LegacyError` strings. Normal consumers print mixed diagnostics and ignore the error replay; quiet consumers print only the error replay; silent consumers print neither. Checked ZIP failures remain typed `MemberFailed` events. See the [guide](zip-checked-reads.md) and [Prybar handoff](prybar-resource-integration.md). This contract does not claim that Prybar has been migrated, pinned, qualified or deployed.
